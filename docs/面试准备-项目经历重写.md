## 一、简历写法

### 项目名称
**市场监管投诉智能分派与合规审查系统**（Multi-Agent Complaint Triage & Compliance Pipeline）

### 核心技术栈
FastAPI · LangGraph · ChromaDB · scikit-learn · PyYAML · Pydantic v2 · structlog · Docker

### 核心职责与产出

#### 1. 规则引擎配置化 — YAML 替代硬编码关键词
将 ClassifierAgent 中 15+ 个硬编码关键词列表（~200 行）迁移到 4 个 YAML 规则文件（accept/reject/dispatch/sensitive，共 27 条规则），通过 RuleLoader + RuleEngine 实现关键词匹配 + 优先级排序。规则从代码中分离后，非开发人员可直接编辑 YAML 调整受理策略，每次变更可通过回放评估验证准确率不下降。

#### 2. RAG 可信度保障 — AnswerVerifier 法规引用真实性校验
在 Reply 节点后插入 AnswerVerifier，做 5 项校验：法规引用是否在 RAG 检索结果中可追溯、检索源是否降级、多条高分法规是否冲突、回复是否含绝对化措辞、是否存在"有引用无检索结果"的幻觉风险。配套构建了 50 条 RAG 评估集 + 评估器（Recall@K/MRR）。

#### 3. 安全护栏强化 — 注入检测 + 过度承诺拦截
实现了 PromptInjectionDetector：6 类注入攻击检测（指令覆盖/角色劫持/提示词窃取/强制受理/跳过法规/代码注入），配套 32 个测试用例。GuardrailsAgent 输出侧新增 4 类过度承诺模式（"保证能退""必定处罚""绝对没问题""包您满意"），自动降级为保守模板。

#### 4. 人工复核闭环 + 冲突检测
新增 3 个复核 API（pending 列表/详情/reject 驳回），confirm 接口扩展了 correct_reason_type / correct_office / reviewer_note / can_use_for_training 字段。训练数据导出时自动检测 3 类冲突：同一文本不同标注（label_conflict）、复核结果覆盖系统决策（decision_override）、模型预测与标注不一致（model_disagreement）。

#### 5. 可观测性 + 工程基础
AgentStep 增加 decision_source 字段（RULE/MODEL/RAG_LLM/FALLBACK），SSE 流增加 node_start/node_end 事件。新增 /readyz 深度健康检查，IP 滑动窗口 Rate Limit 中间件，LangGraph state key 与 node 名冲突修复。
